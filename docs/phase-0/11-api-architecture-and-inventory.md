# Phase 0 API Architecture and Inventory

Scope amendment (2026-10-06): [ADR-011](../decisions/ADR-011-seller-fulfilled-marketplace.md) and [revised scope](22-scope-phasing.md) control this historical baseline. Warehouse, fleet, platform-owned stock, platform goods/COD custody, and unconditional settlement requirements are OUT_OF_SCOPE. Seller stock reservations, seller order processing, delivery visibility, and applicable controls remain required. Authorized safe implementation may proceed; excluded capabilities and older blanket implementation stops do not create release blockers.

**Status:** proposed contract inventory  
**Style:** versioned REST/JSON for application APIs, signed provider webhooks, asynchronous domain events  
**Base path:** `/api/v1`

## 1. API contract rules

- OpenAPI is generated and checked into a versioned contract artifact. Every operation defines authentication, authorization, request/response schema, stable errors, rate-limit class, idempotency behavior, and audit behavior.
- JSON field names use `camelCase`; enum values and error codes use `UPPER_SNAKE_CASE`; timestamps are RFC 3339 UTC; IDs are opaque UUID/ULID strings.
- Money is `{ "amountMinor": 14000000, "currency": "DZD" }`. APIs never use binary floating point for money.
- Localized content returns locale-keyed values or the resolved value plus locale. `Accept-Language` supports `ar`, `fr`, and optional `en`; it never changes business codes.
- Collection endpoints use cursor pagination: `page[after]`, `page[limit]` with a maximum per operation. Filtering and sorting are allowlisted.
- Mutation DTOs reject unknown fields. Files use a short-lived upload intent, quarantine/scan workflow, and asset ID; base64 file bodies are not accepted in ordinary JSON requests.
- `Idempotency-Key` is mandatory for order placement, payment actions, refunds, shipment creation, webhooks, payouts, and other operations marked **Yes**. The server stores actor/scope, request hash, state, and response. Reuse with a different request returns `IDEMPOTENCY_KEY_REUSED`.
- Mutable aggregates use `version` or `If-Match`; stale updates return `VERSION_CONFLICT`.
- Rate-limit headers expose the applicable limit and reset. Limits vary by public, authenticated, authentication/OTP, checkout, admin export, and webhook class.
- A successful create returns `201`; asynchronous acceptance returns `202`; no-content deletion/revocation returns `204`. Validation uses `422`; authenticated permission failure uses `403`; ownership-safe missing resources may use `404`.
- Every response propagates `X-Correlation-Id`. Clients may send a valid value; the edge replaces invalid values.

### 1.1 Standard error envelope

```json
{
  "code": "OUT_OF_STOCK",
  "message": "Localized safe message",
  "correlationId": "01J...",
  "details": {
    "items": [{ "offerId": "...", "availableQuantity": 0 }]
  }
}
```

`code` and machine-readable `details` drive client behavior. `message` is safe and localized for the requested locale. Stack traces, SQL, provider secrets, card data, and internal exception names are never returned.

## 9. Canonical provider ports exposed internally

These are application interfaces, not public HTTP endpoints.

```ts
interface PaymentProvider {
  authorize(command: AuthorizePayment): Promise<ProviderPaymentResult>;
  capture(command: CapturePayment): Promise<ProviderPaymentResult>;
  cancel(command: CancelPayment): Promise<ProviderPaymentResult>;
  refund(command: RefundPayment): Promise<ProviderRefundResult>;
  getStatus(query: ProviderPaymentQuery): Promise<ProviderPaymentStatus>;
  verifyAndParseWebhook(input: RawWebhook): Promise<VerifiedPaymentEvent>;
  reconcile(input: ReconciliationSource): Promise<ProviderReconciliation>;
}

interface ShippingProvider {
  getRates(query: ShippingRateQuery): Promise<ShippingRate[]>;
  createShipment(command: CreateProviderShipment): Promise<ProviderShipment>;
  cancelShipment(command: CancelProviderShipment): Promise<ProviderShipmentStatus>;
  getTracking(query: ProviderTrackingQuery): Promise<TrackingSnapshot>;
  createLabel(command: CreateLabel): Promise<PrivateDocumentRef>;
  schedulePickup(command: SchedulePickup): Promise<PickupBooking>;
  getPickupPoints(query: PickupPointQuery): Promise<PickupPoint[]>;
  verifyAndParseWebhook(input: RawWebhook): Promise<VerifiedShipmentEvent>;
}
```

All command methods receive correlation and idempotency metadata through the canonical command context. Provider secrets and SDK response types remain inside the adapter.

## 10. Compatibility and lifecycle

- Additive compatible fields may enter `v1`; clients ignore unknown response fields.
- Removing/renaming fields, changing meaning, narrowing accepted enum values, or making an optional request field required needs a new API version or a declared migration window.
- Event and webhook contracts have independent schema versions.
- Deprecated operations publish a sunset date and usage telemetry before removal.
